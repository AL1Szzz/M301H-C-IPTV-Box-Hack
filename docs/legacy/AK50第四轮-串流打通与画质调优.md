## 二、断流根因（重要，最初的病根复发）

串流一开始只能撑 11 秒、28 秒就断。电视端弹出提示「**与电脑连接过慢，请降低码率**」，一度误判为网络或解码问题。真实原因是：

1. **牌照方应用崩溃拖垮 `system_server`** —— logcat 里出现  
   `FATAL EXCEPTION IN SYSTEM PROCESS`，同时 `com.konka.mor.tv`、`com.gitvkonka.video`  
   反复 `has died`。这和这台电视最初的「ADB 时连时断、卡 KKTV LOGO」是**同一个病**。  
   Moonlight 是被系统连带杀掉的，不是串流本身的问题。
2. **Sunshine 的显示模式切换** —— `display_device_prep = ensure_only_display`  
   会在串流开始时禁用其他所有显示器，模式切换过程会让会话不稳定（顺带导致电脑黑屏）。

**修复**：

- 把上一轮解冻的 4 个牌照方应用重新冻结（`com.konka.mor.tv`、`com.gitvkonka.video`、  
  `com.cibn.tv`、`com.bestv.mishitong.tv`）→ 冻结数回到 **34**，  
  `system_server` 恢复存活，可用内存从 271MB 回到 **327MB**。
- 显示模式改为 `verify_only_active` → 不再动物理屏。

修复后实测：串流稳定 **6 分 13 秒**（00:07:15 → 00:13:28），是修复前的 10 倍以上。

> 结论：**牌照方那几个应用是这个系统的不稳定源**，不要为了看直播去解冻它们。  
> 想看电视台走串流或 DTMB 搜台，别指望这些 App。

## 三、扩展显示模式（电脑不再黑屏）

`E:\tool\Sunshine\config\sunshine.conf` 改动（原文件已备份为 `sunshine.conf.bak_*`）：

```diff
- display_device_prep = ensure_only_display
+ display_device_prep = verify_only_active
```

- `ensure_only_display`：串流时**禁用其他显示器** → 电脑黑屏（原来就是这样）
- `verify_only_active`：只保证目标屏可用，**不动物理屏** → 电脑正常显示

改完执行了 `displayswitch.exe /extend`，并重启 `SunshineService`。  
验证：物理屏 3440x1440（HKM3400）与虚拟屏 1280x720（MTT1337 / Zako Display Adapter）  
**同时 Active**，电脑不黑屏。

当前串流捕获的是**主屏 3440x1440 缩放到 1280x720**（带鱼屏到 16:9 会有黑边）。  
如果想让电视真正当「第二块屏」用（把窗口拖过去），需要让 Sunshine 捕获虚拟屏 ——  
目前虚拟屏在串流时会被系统收掉（日志 `Client-specified display ... not found, using default display`），  
留待后续处理。

## 四、画质档位与一键脚本

排查期为了定位断流，把码率一路压到 **2500 kbps / 720p / 30fps**，画质很差——  
**这是临时手段，根因修好后应该调回去**。

电视走的是**有线网口 eth0**（`dhcp.eth0.ipaddress = 192.168.50.104`），  
带宽不是瓶颈；真正限制是 Mali-T720 的解码能力。

### 一键脚本 `stream_connect.py`

```bash
cd C:\Users\Administrator\Downloads\AK50-Root精简

python stream_connect.py --preset medium   # 推荐起点：1080p 30fps 12Mbps
python stream_connect.py --preset high     # 1080p 60fps 20Mbps，卡就降
python stream_connect.py --preset low      # 720p 30fps 6Mbps，保底
python stream_connect.py --quality-only    # 只改参数，不发起串流
```

脚本自动完成：连 ADB → 提 root → 用 `busybox sed` 写参数 → `uiautomator dump`  
定位电脑条目坐标 → 坐标点击 → 确认启动。（方向键焦点在这台电视上不可靠，  
坐标点击才稳；电视没有原生 `sed`，必须 `busybox sed`。）

| 档位         | 分辨率       | 帧率 | 码率         | 适用           |

| high       | 1920x1080 | 60 | 20000 kbps | 画面最好，老芯片可能吃力 |
| **medium** | 1920x1080 | 30 | 12000 kbps | **推荐先试这个**   |

## 六、本轮踩到的坑

- 电视端弹「连接过慢」**不一定**是网络：这台机器是 system_server 崩溃导致的，  
  先查 `logcat | grep "FATAL EXCEPTION IN SYSTEM PROCESS"`。
- Moonlight 的 PcView 焦点行为不稳定（有时默认在设置按钮，有时在电脑条目），  
  方向键不可靠 → 用 `uiautomator dump` + `input tap` 坐标点击。
- 电视 `/system/bin/sh` 下没有 `sed`/`head`/`sort`，只有 busybox 里有；  
  写 adb shell 脚本时注意。
- `reg.exe` 被安全策略拉黑，查浏览器路径要用 PowerShell 的 `Get-ChildItem`。
- 无头 Edge（`--headless=new --dump-dom`）在本机输出 0 字节，抓 SPA 页面这条路不通。
