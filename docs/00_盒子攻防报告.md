## 二、ADB 攻防：12 条路，全部走完

| # | 方法 | 结果 |
|---|---|---|
| 1 | 全端口扫 + 真实 adb connect × 9 端口 | 全部 failed，5555 拒绝连接 |
| 2 | 7546 端口 Digest 认证，168 组账密 | **全是 200**，认证是空壳桩，无功能 |
| 3 | 4008 CyberHTTP 各种路径/RTSP/POST | 一律 400，海思私有协议 |
| 4 | 遥控器/工程模式：版本号连点、472635、782782323、F2/F3、其他设置连按右键 | **全部无效**（遥控器无数字键） |
| 5 | U 盘装 APK 自动开 ADB（自编 StbTool） | 能装，但之前**秒退** |
| 6 | 排查助手里改 ADB 端口号 + 确认 | 端口值能改，但 **adbd 不起来** |
| 7 | app 内 `setprop service.adb.tcp.port` 5555 / **5556→5555 强制变值触发** | rc=0，值确实变了，但 **adbd 仍 stopped**（无 init 触发器） |
| 8 | `setprop persist.service.adb.enable 1` / `persist.sys.usb.config adb` / `sys.usb.config adb` | rc=0 但**值没变**（属性被静默丢弃） |
| 9 | `setprop ctl.start adbd` / `start adbd` | rc=0，**无效**（init 对非 system uid 静默拒绝） |
| 10 | `su`（7 种语法） | **`uid 10060 not allowed to su`**；且 su 是 `-rwxr-xr-x root shell`，**没有 setuid 位** → 根本不可能提权 |
| 11 | 直接 exec `/sbin/adbd` | Permission denied（/sbin 目录不可读不可执行）；/system 下没有 adbd |
| 12 | OTA 刷签名包 | 证书是创维自有密钥，**无私钥 → 签不了** |

### 关键结论
1. 这台盒子的属性服务有**自定义白名单**：只有 `service.adb.tcp.port` 能被普通 app 写（就是给排查助手用的），
   但 **init 上没有对应的 `on property` 触发器**，所以写完了也没人去 start adbd。
2. **`su` 不是 setuid** —— 所有 su 路线都是死路，以前"装个 su 提权"的想法可以彻底放弃。
3. app 权限（uid 10060）能做的事非常有限：
   - `am force-stop` → SecurityException（`FORCE_STOP_PACKAGES`）
   - `settings put/get` → SecurityException（`ACCESS_CONTENT_PROVIDERS_EXTERNALLY`）
   - `pm disable` / `pm clear` / `pm install` → **进程被 Killed**
   - `am start -n` → SecurityException（`INTERACT_ACROSS_USERS_FULL`）

## 四、免 U 盘传文件：已验证可行

U 盘拔掉也能传！原理是**盒子反过来从电脑拉**：

```bash
# 电脑（先起服务）

# 盒子（/cmd 里执行）
/system/xbin/nc 192.168.50.213 18888 > /mnt/sdcard/xxx.apk
```

## 五、明天继续的路线（按推荐排序）

### 方案 A：DirtyCOW 提权（**最推荐**）
内核 **3.18.24**（2018 编译），DirtyCOW（CVE-2016-5195）在该分支要 **3.18.42+** 才修好，
**3.18.24 < 3.18.42 → 大概率仍然中招**。

做法：
1. 找一个 ARM 版 dirtycow PoC（网上有现成的 `dirtycow` / `run-as` 版）
2. 用 nc 推到 **`/data/local/`**（可写可执行）
3. 用它覆写一个 root 拥有的可执行文件 → 拿到 root → `setprop ctl.start adbd` → **root ADB**
4. 有 root 后一切照旧：冻结应用、去广告、改自启

风险：有极低概率崩，建议先只覆写一个无关文件验证漏洞存在，再动真格。

### 方案 B：挖 `com.cmcc.mid.softdetector`（智能排查助手）
它是**普通 app**（无 sharedUserId），却能显示/改 ADB 端口 —— 说明存在某条我们还没找到的通道。
它的 dex 被 **cmccshell 加壳**，真代码在 `assets/shell.cmcc/classes2_37190.dex`（加密）。
下一步：脱壳（dump 内存 dex）或者看它有没有导出 AIDL 服务（`thomas.permission.AIDL_SERVICE`）。
另外 `com.mipt.rs`（RemoteService）、`com.cmcc.silenceinstaller`（静默安装器）也值得挖。

### 方案 C：继续找 init 触发器
`getprop` 全量已存盘，可以逐个排查还有哪些属性能被 app 写成功
（目前只确认了 `service.adb.tcp.port`），看看有没有漏网的触发器。
